## 2. 📐 整体设计哲学

### 2.1 双轨制(GEMINI.md 明确)

Lucky 体系有**两条严格隔离的预测/写入轨道**,防止相互污染:

| 轨道 | 写入位置 | 适用对象 | 格式 |
|---|---|---|---|
| **主历史 CSV** | `data/ai_predictions_history.csv` | 外部 LLM(Gemini、Qwen、Kimi、DeepSeek、Llama、MiniMax API) | 8 列 RFC 4180 |
| **Lucky 本地 JSON** | `data/backtest/*.json` | FSW、V3-V22、自适应、形态约束、配额选号等本地算法 | 每期独立 JSON |

**为什么分开**:
- CSV 是 Streamlit UI(`views/ai_assistant.py:render_ai_analysis()`) 的统一存档入口,格式改动风险高
- JSON 是 Lucky 的私有档案,可以灵活演化
- 防止外部 LLM 和本地算法**互相污染**同一个数据源

### 2.2 评分函数 vs 启发式约束

Lucky 的本地算法采用**两段式设计**:
1. **评分函数**:给 80 个候选号打分(0-2 分范围),按分数排序
2. **启发式约束**:在评分排序基础上,叠加若干过滤/替换规则(如 4 区位配额、lag 重号检验、形态约束)

**核心理念**:**信号弱 + 约束优先**。因为快乐8 每期 80 选 20,理论随机命中 25%,信号非常微弱,所以更倾向于"避免明显错误"(重号过多、4 区位失衡)而非"追逐精确信号"。

## 3. 🧬 V22 系列模型族(主力)

V22 是当前最成熟的本地评分体系。基线 **V22.A** 衍生出 **A1-A6** 子方案 + **D1** 重号检验变种。

### 3.1 V22.A 基线评分(2026-07-30)

**评分公式**(对每个候选号 n,基于 n 在最近 5/10/30 期的出现次数 c5/c10/c30):

```python
# c5 评分 (最近 5 期出现次数)
s[c5 == 0] = -0.5  # 极冷,略降权
s[c5 == 1] = 0.0   # 冷,中性
s[c5 == 2] = +0.2  # 温,加分
s[c5 == 3] = +0.2  # 偏热,加分
s[c5 == 4] = -0.3  # 热,降权
s[c5 == 5] = -0.8  # 很热,大幅降权
s[c5 >= 6] = -1.5  # 过热,强降权

# c10 评分 (最近 10 期出现次数)
t[(c10 >= 2) & (c10 <= 4)] = 1.0  # 黄金区间
t[c10 == 1] = 0.4
t[c10 == 0] = 0.2
t[(c10 >= 5) & (c10 <= 6)] = -0.3
t[c10 >= 7] = -0.8

# c30 评分 (最近 30 期出现次数)
u[(c30 >= 5) & (c30 <= 10)] = 0.5  # 黄金区间
u[(c30 >= 3) & (c30 <= 4)] = 0.2
u[c30 <= 2] = -0.2
u[c30 >= 13] = -0.7

# 邻号 (last_i 的 ±1, ±2)
nbr = compute_neighbors(last_i)  # 每个邻号 +0.3, 总和归一

# 综合分
score = s + t + u + nbr
```

**4 区位配额(80 号分 4 个区位,每区 20 个号)**:
- 1区: 1-20
- 2区: 21-40
- 3区: 41-60
- 4区: 61-80
- 严格模式:每区选 5 个(5/5/5/5 = 20 胆)
- 宽松模式:每区选 3-8 个

**4 胆/6 胆/10 胆**:从 20 胆中按评分前 N 个选,不约束 4 区位。

### 3.2 V22.A 子方案(A1-A6)

| 子方案 | 核心改动 | 设计动机 | 200 期 Top 4 命中率 |
|---|---|---|---|
| **V22.A** | 基线 | 默认 P90 + 4 区位配额 + 邻号 | 25.49% |
| **V22.A1** (方案 F) | 加 c2_hot=0.6, c3_hot=0.4 加分 | 偏热号 | 22.88% (无提升) |
| **V22.A2** | 4 区位放宽到每区 3-8 | 避免过度约束 | 22.62% |
| **V22.A3** | 加 lag1-3 单期阈值约束 | 防止 20 胆与上期重叠过多 | 22.62% |
| **V22.A4** | 加 lag1-5 逐一替换末尾 2 个 | 防止短期重复过多 | 22.50% |
| **V22.A5** | c5 评分三轮调整(预留位) | 偏好温热平衡 | (未独立实现) |
| **V22.A6** ⭐ | **自适应冷热号比例**:observed - baseline | 跟随近期偏好 | **27.28%** ⭐ |

**V22.A6 的核心公式**:
```python
def score_v22_a6(last_i, lookback=3, scale=2.0):
    # 计算 observed 分布:近 3 期开奖的 c5 分布
    observed = compute_observed_c5(last_i, lookback=3)
    # baseline 分布:全部 80 号的 c5 平均分布(预计算)
    baseline = BASELINE_C5  # dict: c5 → 占比
    
    # 调整:observed - baseline, scale=2.0
    for k in range(6):
        score[c5 == k] += (observed[k] - baseline[k]) * scale
    
    return score, observed
```

**V22.A6 效果**(200 期回测):
- Top 4 平均命中率 **27.28%** (V22.A 原版 25.49%, **+1.79pp**)
- Top 6 ≥3中 14.6% (原版 12.0%, +2.6pp)
- Top 10 平均 26.35% (原版 25.60%, +0.75pp)
- **偏热号从 0.1% → 15.2%**(自适应机制激活)

### 3.3 V22.D1:重号检验变种(2026-08-09)

**核心思想**:20 胆与最近 5 期开奖的"重号数"不能超过阈值。

```python
# 阈值设计(基于近 500 期实际开奖 lag 重号分布)
lag_thresholds = {
    'lag1': 9,  # P95 水平
    'lag2': 9,
    'lag3': 9,
    'lag4': 9,
    'lag5': 9
}

# 触发后:替换 20 胆中评分最低的 1 个号
for lag, threshold in lag_thresholds.items():
    overlap = len(set(20_dan) & set(data[last_i + lag]))
    if overlap > threshold:
        # 找候补号(不与该 lag 重,不破坏 4 区位 5/5/5/5)
        replace_lowest_scoring(20_dan, candidate_pool, lag, threshold)
```

**设计哲学**:用户问题驱动 — "实际开奖中,与上一期的重号数量应该是 7 左右吧,设置 12 是否太多了?" → 经查证:实际开奖 lag1 重号平均 5,P75=6,P95=7,max=12 → **阈值 9 = P95+ 水平**。

**V22.D1 vs 已有变种**:
| 变种 | 重号约束方式 |
|---|---|
| V22.A3 | lag1-3 单期阈值(贪心构造时跳过) |
| V22.A4 | lag1-5 逐一替换末尾 2 个 |
| **V22.D1** | **lag1-5 同阈值(9),只在超阈值时替换末尾 1 个** ⭐ |

### 6.2 极端反转期失败

**2026-08-28 复盘**:2026229 期 (和值 1141,4 区 11 个) → 2026230 期 (和值 780,4 区 4 个)
- 剧烈反转让**所有模型偏离实际开奖**
- V22.A6 自适应机制在反转期反而强化了错误信号
- V22.D1 重号阈值在反转期反而限制了"重启信号"

**教训**:
- 单期极端值(和值 P90+ 或 4 区位 P95+)应触发"形态重置"信号
- 模型应保留"完全重启"选项(忽略所有近期偏好)

### 6.3 5 期均值的脆弱性

近 5 期 vs 近 30 期均值差异巨大:
- 近 5 期 4 区缺失(3.4 个) → 30 期均值 4 区正常(5.0 个)
- 5 期均值被 2026222 (627, 4区=2) 和 2026229 (1141, 4区=11) 等极端值拉偏

**教训**:**用 10-30 期滚动均值判断近期形态,不要用 5 期**。
